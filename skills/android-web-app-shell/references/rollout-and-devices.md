# 部署影响、设备边界与生产验收

## 决定本次要发什么

| 改动 | 发布与核实 |
| --- | --- |
| 仅网页布局、文案或已有壳的能力识别 | 构建实际前端入口；核对正式 HTML 引用的 JS/CSS 及其摘要。检查 Service Worker 和资源缓存策略；只为修缓存而清除应用数据会丢失登录。 |
| 原生标记、文件能力、主题资源或服务行为 | 出对应 APK，核实设备实际安装的版本和签名。依赖新网页时也发布前端，并为新旧网页与壳组合定义可用能力。 |
| 新增后端端点或投递资格字段 | 核对现有数据库的迁移记录和备份，按项目迁移差异增量更新，保留生产库、媒体和配置。纯运行时或路由改造可以没有新迁移。 |
| 增加独立监听服务或变更公开路由 | 同时核对依赖、安装／启停／检查脚本、真正发送通知的各个进程和反向代理。先验证本机服务，再校验配置、切换路由、做公网验收。回退时先恢复可工作的路由，再停新增服务。 |

WePass 的实际部署将网站 API 留在 Waitress 回环端口 8009，仅将 Android 通知的精确路径转发至 18009。后者的 TCP 承载等待请求，UDP 接收本机提交提示。代理传递 Host 与 HTTPS 协议头，读超时覆盖服务端长等待；客户端超时也要留余量。Windows 使用独立服务及计划任务，需同步中央 Nginx 配置和运维实际使用的服务器版脚本，确认导出的脚本编码可执行。前端部署复制 dist **内的内容**到约定静态根目录。以上取值和目录属于该部署实例。

## 使用用户指定的设备

1. 先列出已连接设备，按用户指定的序列号选定每条 ADB 命令的目标；同时连接了 USB 真机时尤其要核实。遇到“模拟器已在某进程运行”先对照设备和进程。不要自行开第二台、结束进程、删锁或清空 AVD。
2. 记录已装包、版本、签名、当前页面与登录、系统外观及本次需改动的设置。覆盖安装遇到签名冲突时保留数据；有同签名测试构建可验证功能，另记正式 APK 的独立验签结果。
3. 本机联调可采用独立包名、回环测试域、临时数据库和显式端口转发。记录端口占用与测试前状态，仅撤销本次建立的映射。验证生产时切回正式 HTTPS，使用用户已授权的登录会话和最少的测试通知。
4. 实测结束后恢复系统外观、应用偏好、锁屏等临时设置。若设备未连接，继续完成构建、资源比对和本地回归，按实际情况列出待测的设备层。

## 证据与结果

- **生产入口**：检查正式域名、关键静态资源与本地发布产物一致、健康接口和匿名／登录接口的预期响应。匿名返回 401 只能证明该入口要求认证；首页 200 也不能证明后台等待服务正常。
- **单台设备**：从真实页面触发测试，记录设备、版本、账号推送开关及系统权限。以系统通知栏及业务消息标识确认入栏，站内记录单独记录。点入通知、打开设置、返回及重开后分别检查。
- **多台与锁屏**：同一账号多设备同时在线时，从一个入口触发一次，逐台核对同一条；另一账号应保持隔离。分别记录退后台、划掉最近任务、锁屏静置、断网重连和强行停止，不混用结论。开始锁屏计时前核实实际锁定／熄屏状态。使用真实业务触发时考虑每日限额与免打扰，事先规定时间窗、重复次数与计时依据。
- **报告口径**：本地 16 个独立会话同收能证明服务端并发语义；一台模拟器连接正式站收到通知能证明该设备的线上链路。国内厂商真机、实际锁屏展示、第二台实体设备分别需要对应证据。已测层级可以交付，缺少证据的承诺写成待验证项。
